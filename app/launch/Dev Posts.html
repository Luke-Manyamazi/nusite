We built NuSite to fix the messy, 2015-era code we kept inheriting

              

                
showdev

                
ai

                
webdev

                
productivity

              


              

                
TL;DR — We just launched NuSite, an AI engine that takes any old website and hands you a modern, deployable one back. Paste raw HTML, upload a ZIP, drop a URL, or connect a GitHub repo — pick one of 8 transforms, and ship the output to Vercel, Netlify, Cloudflare, GitHub Pages or cPanel with a deployment guide tailored to your host. There's a free tier. Today is launch day on Product Hunt.


                
The problem we kept hitting

                
Every developer who has done client work has lived this loop: you inherit a site, you open the repo, and you find a <table border="1"> tagged shrine to early-2010s web. The owner just wants it to not look broken on a phone. You quote them three weeks because rewriting it cleanly is three weeks. They go quiet. You feel slightly responsible. Nothing ships.

                
We had this experience enough times that it stopped feeling like a quirky anecdote and started feeling like a market.

                
"Stop spending days cleaning up client sites." — every freelancer we've ever talked to, paraphrased.


                
What NuSite actually does

                
You give it the source — paste, ZIP, URL, or GitHub repo. You pick a transform:

                
    
                  
  • Static → Responsive — fluid grids, breakpoints, sane touch targets
    • 
                  
  • HTML → React — clean component tree with props and routing
    • 
                  
  • Modernise Design — type system, spacing, colour brought into this decade
    • 
                  
  • Add Dark Mode — token-driven, respects prefers-color-scheme
    • 
                  
  • Performance Fix — image/font/JS/CSS surgery for Lighthouse 90+
    • 
                  
  • Accessibility Audit — focus rings, ARIA, contrast, the boring stuff that matters
    • 
                  
  • Convert to Tailwind — strip stale styles, port to utility classes
    • 
                  
  • Add CSS Motion — tasteful entrance and scroll-reveal animations
    • 
                

                
The model reads the whole site as context — it isn't a per-file find-and-replace. It outputs a clean tree of files, a side-by-side diff, and a deployment guide for the host you tell it you're using.


                
Why we didn't just write a Chrome extension

                
Two reasons. First, the interesting work happens across files — restructuring a layout, lifting state into components, replacing a CSS file rather than monkey-patching a page. Second, the deployment guide is half the value. Most "modernise my site" tools end the moment they show you new code. We didn't want to end there. The post-transform screen asks where you're hosting and writes you the exact set of commands.


                
$ git init && git add -A
$ git commit -m "nusite: modernised"
$ vercel --prod

✓  Building project
✓  Deployed to acme.vercel.app
✓  Linked custom domain


                
What's hard about this

                
Three things took longer than we expected:

                
    
                  
  • Holding the whole tree in context without losing track of which file you're editing. We ended up with a planning pass that reads structure first, then a transformation pass per file with the plan as anchor.
    • 
                  
  • Knowing when to stop. Models love to rewrite everything. We had to build heuristics for "this file is fine, leave it alone."
    • 
                  
  • Diffs people can actually trust. If you can't see what changed and why, you won't ship the output. We landed on file-level summaries plus an inline diff you can step through.
    •
